### P0-3 沙箱可读 `.env` 与后端源码 ✅ import 通道已封

**位置**：`backend/app/sandbox/executor.py`

`.mstar` 审计 #3 早已标注「subprocess 沙箱在 Windows 无有效隔离：rlimit 不生效、socket 补丁可绕过、**可读 `.env`**」（HIGH）。
`_clean_env()` 的注释写着「刻意排除 PYTHONPATH……否则沙箱代码可 `import app.config` 直接读取后端密钥」——
**这个防护是无效的**。根因：项目 editable 安装生成的 `math_model_agent.pth` 内容就是
`D:/_Projects/math_agent/backend`，由 `site` 模块在**解释器启动时无条件**写进 `sys.path`，与 PYTHONPATH 无关。

**实测复现**（修复前，真实子进程）：

```
import app.config          → IMPORT_OK                          # 注释里的防护完全没生效
open('<repo>/backend/.env') → ENV_READABLE len=1367 HAS_JWT_SECRET=True
socket.create_connection    → NET_BLOCKED: OSError               # socket 补丁本身有效
```

**已实施的修复**（`_wrap_code` 生成的前置码，双重处置）：

1. 把仓库根与 `backend/` 从 `sys.path` 剔除；
2. 在 `meta_path` 最前端注册 `_BlockBackendSource` finder，永久屏蔽 `app` / `math_model_agent` 顶层包——
   即便用户代码把路径重新加回 `sys.path` 也 import 不到。

同步修正了 `_clean_env()` 那条已被证伪的注释，避免后人继续被误导。

**修复后实测**：

```

socket.create_connection   → NET_BLOCKED: OSError                ✅（未回归）
numpy/pandas/sympy/matplotlib 全部可用，图表正常捕获            ✅（未误伤）
```

新增回归测试 `tests/test_sandbox_source_isolation.py`（6 个用例，含「sys.path 重新注入后仍应被屏蔽」与

**⚠️ 残余风险（按用户决定保留）**：绝对路径 `open()` 读 `.env` 仍可行。要利用需同时满足

### P1-1 SSRF 校验对域名无效（未修，已知取舍）

`_validate_custom_base_url` 只校验 `scheme == https` 与**字面 IP** 是否为内网；域名形式直接
`pass` 跳过（代码注释自述「本地单机应用的务实取舍」）。字面量 IP 已覆盖 `169.254.169.254`
云元数据等，但 `https://internal.corp.local` 这类内网域名可穿透。建议补一步
`socket.gethostbyname` 解析后再判内网。

另：`create_api_key` 未校验 `provider` 是否在 `PROVIDER_PRESETS`（`quick_add_api_key` 校验了），
传入未知 provider + 空 base_url 时会拼出 `/v1/chat/completions` 相对 URL，属于健壮性小瑕。

### P1-2 访客共用桶 + 无速率限制（未修）

`resolve_user_id` 对未登录用户返回 `"default"`：所有访客共享同一份 API Key 池、可互相删除，
且 `/api/apikeys/quick` 会**真的向外网发一次验证请求**——无速率限制时可被用来消耗额度。建议加 per-IP 限流。

### P2-1 `pytest.ini` 的 `addopts = -q` 吞掉汇总行（未修）

`python -m pytest` 只输出进度点、**不输出 `N passed` 汇总行**（quiet 模式叠加），
只能靠退出码判断成败。建议改为 `addopts = -ra` 或去掉 `-q`。

## 五、CI 修复记录（2026-10 当日闭环）

首次推送后 CI 连挂三轮，全部 15 个失败集中在新加的两个测试文件（存量 194 个测试在 CI 上一直全过）。
两个独立根因，外加测试改造后暴露出的一个真实产品缺陷：

### 5.1 测试依赖了被 gitignore 的 `.env`

`app.main` 的 lifespan 在 `jwt_secret` 为默认值 `"set-in-env-file"` 且 `debug=False` 时直接
RuntimeError。CI 上没有 `backend/.env`（被 .gitignore），于是 9 个用 TestClient 的用例全部起不来。
此前没有任何测试启动过 FastAPI app，所以这个坑一直没暴露。

**修复**：新增 `backend/tests/conftest.py`，autouse fixture 保证测试进程内有可用 secret。
生产启动路径的强校验保持不变——改的是测试环境，不是产品默认值。

### 5.2 docker 可用但镜像未构建时没有回退

CI runner 上 docker daemon 可用，但 `mathmodel-sandbox` 是本地构建的镜像、runner 上没有，
`docker_daemon_up()` 返回 True 于是走 docker 模式，每次执行都挂在 "pull access denied"。
**这同时是真实产品缺陷**：代码声称「docker 不可用自动回退 subprocess」，却没处理「docker 可用但镜像缺失」。

**修复**：`executor` 新增 `docker_image_ready()`（带 60s 缓存），`run()` 改为 daemon 与镜像
两者都就绪才走 docker，缺任一即回退；`/api/sandbox/status` 补 `docker_image_ready` 字段，
修正原先「报硬隔离实际在跑 subprocess」的口径错误；CI 增加 `docker build` 步骤，
让 Docker 硬隔离路径真正被跑到（构建失败不阻塞，executor 会回退）。

### 5.3 `--cap-drop=ALL` 导致沙箱输出目录不可写（测试改造后才暴露）

把沙箱测试从「断言 subprocess 专属错误文案」改成「断言安全不变量」后，CI 走到 Docker 模式，
立刻抓到：`PermissionError: [Errno 13] Permission denied: 'smoke.png'`。

根因：`--cap-drop=ALL` 会把 `CAP_DAC_OVERRIDE` 一起丢掉，容器内 root 不再能绕过文件权限位；
而 `output_subdir` 由宿主进程创建（runner 上 uid 1001 / mode 755），容器内进程对它只是
"other" → 只读。**LLM 生成的建模代码用相对路径存图是常态，等于 Docker 模式下图表功能整体不可用。**
本地不复现是因为 Windows 上 Docker 走 WSL2 后端、目录属主不同，只有 Linux runner 会命中。

### 5.4 测试写法本身的教训

- 曾想在 pytest 进程内 exec 沙箱前置码来快速验证屏蔽逻辑，结果前置码把 `_BlockBackendSource`
  插进了**真实** `sys.meta_path`，把同会话后续的 `import app.main` 全部毒死。已删除该用例并注释说明。

## 八、本轮新增的过程教训

1. **不要用 PowerShell 文本 cmdlet 改源码**。为修一个 `E741`（变量名 `l`）用了
   `Get-Content | -replace | Set-Content`，结果文件被写入 **BOM**，`ast.parse` 直接失败。
   AGENTS.md 早有此禁令（中文注释变乱码），这次是同一教训的另一种表现形式。
   已用 Python 移除 BOM 并验证中文完好。
2. **`git commit --amend` 改的是 HEAD，不是你指定的提交**。我以为在把 5 个文件删除
   并进 KB 提交，实际并进了后面的 chart-templates 提交。已 `reset --soft` 后重新分组。
3. **`Get-ChildItem` 列不到已删除的文件**，所以 `git add <路径列表>` 会漏掉 deletion。
   删除必须显式 `git rm`（或单独 `git add` 那些路径）。
4. **探针脚本自己的路径格式要和被测代码一致**。我第一版索引对比脚本用了相对路径，
   而哈希库用绝对路径 + 当时的英文目录名，结果 157 个文件全被判为「已变化」、
   193 个全判为「已删除」——差点据此做出错误决策。改用工具自带的 `--incremental` 才准。
