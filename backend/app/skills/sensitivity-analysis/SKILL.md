# 验证与灵敏度分析规范

## 一、验证必须覆盖四类检查

1. **正确性检验**：量纲是否一致；边界情形（变量取 0、取极大）结果是否合理；与题目中的常识或已知结论是否冲突；
2. **灵敏度分析**：对 1～3 个**关键参数**做扰动（建议 ±10% 与 ±20%），观察目标值的相对变化；
3. **稳健性检验**：更换求解方法或改变初始值，结论是否一致；
4. **误差分析**：数据误差/模型简化带来的影响量级。

## 二、灵敏度分析的执行约定

- 每次只扰动一个参数（单因素），必要时再补关键参数的组合扰动；
- 结果必须用表格呈现，列为：`参数 | 基准值 | 扰动量 | 目标值变化 | 相对变化率 | 结论`；
- 判据要**事先说清**：例如「参数 ±20% 时目标值变化 < 10% 视为稳健」。判据不能事后按结果编；
- 明确指出哪些参数是**敏感参数**（变化放大）——这些参数需要更高精度的数据支撑。

## 三、PASS / FAIL 判定

- PASS 的条件必须可复现：正确性检查无矛盾 + 关键参数扰动下结论方向不变；
- FAIL 时必须说明**失败原因**（哪个检查、哪个参数、变化多少），因为该原因会被回传给建模/求解环节重做（本平台的流水线会自动回退并注入该原因）；
- 不允许出现「大致通过」「基本合理」这类无法验证的表述。

## 四、必须自查的坑

- 只做灵敏度分析、跳过正确性与误差分析；
- 扰动幅度随意（既非 ±10% 也无依据），或只扰动不敏感的参数做样子；
- 给出 PASS 却没有任何数值支撑；
- 发现模型不稳，却把结论写成「模型整体良好」。
