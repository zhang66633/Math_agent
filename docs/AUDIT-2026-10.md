## 二、安全发现（按严重度）

### P0-1 任务系统零隔离 ✅ 已修复

**位置**：`backend/app/api/tasks.py`、`backend/app/api/ws.py`

`get_task` / `get_task_messages` / `get_task_files` / `get_task_events` / `get_task_status` /
`cancel_task` / `export_document` / `download_package` 全部注入了
`user: GitHubUser | None = Depends(get_current_user)`，但**函数体内从未使用该参数**——
直接 `get_session_manager().get(task_id)`，无任何属主校验。`GET /api/tasks` 连鉴权依赖都没有。
`ws.py` 更宽松：只 `decode_jwt` 不校验，任何拿到 task_id 的人都能订阅他人任务的实时执行过程。

**实测复现**（修复前，不起任何 token）：

```
GET  /api/tasks                              → 200，返回全部 71 个任务的问题原文
GET  /api/tasks/{id}/messages                → 200，返回他人任务 6 条消息
POST /api/tasks/{id}/cancel                  → 200 {"success":true,"message":"任务已取消"}
```

**修复**：

- `SessionManager` 增加 `owner` 字段与 `get_owned()` / `list_for_owner()` / `cancel(owner=...)`；
  裸 `get()` / `list_all()` 保留给编排器线程等内部调用方，并在 docstring 里标注「HTTP 层禁用」。
- `tasks.py` 全路由收口到 `_owned_task_or_404(task_id, resolve_user_id(user))`，
  未授权一律回 **404 而非 403**（不泄露 task_id 是否存在）。
- `ws.py` 按 token 解析归属后先校验属主，非属主 `close(1008)` 且**不接受连接**。

**修复后实测**（真实 HTTP，18/18 通过）：A 登录只见自己的 0 个任务、
读/取消/导出/打包 B 的任务全部 404、访客读 guest 任务仍 200（存量兼容）、画像按 login 隔离。

**存量数据处理**：`sessions.json` 里 71 个无 `owner` 字段的任务**统一视为 guest**（不重写文件）。
即单机自用场景行为不变；跨用户场景不再泄露。若想把它们划给具体账号，改 `owner` 字段即可。

**状态**：`.mstar/plans/audit-2026-08-14` 计划项 005「暴露面收敛：会话/**task**/files 鉴权」标记为
DONE，但只完成了「config/.env 收紧 + **会话**隔离」，task/files 部分实际未做。属**已知未闭合项**。

### P0-3 沙箱可读 `.env` 与后端源码 ✅ import 通道已封

**位置**：`backend/app/sandbox/executor.py`

`.mstar` 审计 #3 早已标注「subprocess 沙箱在 Windows 无有效隔离：rlimit 不生效、socket 补丁可绕过、**可读 `.env`**」（HIGH）。
`_clean_env()` 的注释写着「刻意排除 PYTHONPATH……否则沙箱代码可 `import app.config` 直接读取后端密钥」——
**这个防护是无效的**。根因：项目 editable 安装生成的 `math_model_agent.pth` 内容就是
`D:/_Projects/math_agent/backend`，由 `site` 模块在**解释器启动时无条件**写进 `sys.path`，与 PYTHONPATH 无关。

**实测复现**（修复前，真实子进程）：

```
import app.config          → IMPORT_OK                          # 注释里的防护完全没生效
open('<repo>/backend/.env') → ENV_READABLE len=1367 HAS_JWT_SECRET=True
socket.create_connection    → NET_BLOCKED: OSError               # socket 补丁本身有效
```

**已实施的修复**（`_wrap_code` 生成的前置码，双重处置）：

1. 把仓库根与 `backend/` 从 `sys.path` 剔除；
2. 在 `meta_path` 最前端注册 `_BlockBackendSource` finder，永久屏蔽 `app` / `math_model_agent` 顶层包——
   即便用户代码把路径重新加回 `sys.path` 也 import 不到。

同步修正了 `_clean_env()` 那条已被证伪的注释，避免后人继续被误导。

**修复后实测**：

```
import app.config          → IMPORT_BLOCKED: ImportError         ✅
socket.create_connection   → NET_BLOCKED: OSError                ✅（未回归）
numpy/pandas/sympy/matplotlib 全部可用，图表正常捕获            ✅（未误伤）
```

新增回归测试 `tests/test_sandbox_source_isolation.py`（6 个用例，含「sys.path 重新注入后仍应被屏蔽」与
「科学计算栈不得被误伤」两条护栏）。

**⚠️ 残余风险（按用户决定保留）**：绝对路径 `open()` 读 `.env` 仍可行。要利用需同时满足
①知道绝对路径（可猜测）②绕过网络阻断外传。**解法是 Docker 硬隔离**——用户明确「Docker 可启动但目前不需要」，
故维持 subprocess 并接受该风险。

### P1-1 SSRF 校验对域名无效（未修，已知取舍）

`_validate_custom_base_url` 只校验 `scheme == https` 与**字面 IP** 是否为内网；域名形式直接
`pass` 跳过（代码注释自述「本地单机应用的务实取舍」）。字面量 IP 已覆盖 `169.254.169.254`
云元数据等，但 `https://internal.corp.local` 这类内网域名可穿透。建议补一步
`socket.gethostbyname` 解析后再判内网。

另：`create_api_key` 未校验 `provider` 是否在 `PROVIDER_PRESETS`（`quick_add_api_key` 校验了），
传入未知 provider + 空 base_url 时会拼出 `/v1/chat/completions` 相对 URL，属于健壮性小瑕。

### P1-2 访客共用桶 + 无速率限制（未修）

`resolve_user_id` 对未登录用户返回 `"default"`：所有访客共享同一份 API Key 池、可互相删除，
且 `/api/apikeys/quick` 会**真的向外网发一次验证请求**——无速率限制时可被用来消耗额度。建议加 per-IP 限流。

### P2-1 `pytest.ini` 的 `addopts = -q` 吞掉汇总行（未修）

`python -m pytest` 只输出进度点、**不输出 `N passed` 汇总行**（quiet 模式叠加），
只能靠退出码判断成败。建议改为 `addopts = -ra` 或去掉 `-q`。
